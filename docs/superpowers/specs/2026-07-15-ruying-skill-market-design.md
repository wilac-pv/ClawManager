# 如影 Code Skill 市场设计

日期：2026-07-15

状态：已确认

目标代码线：`ruying-code-oem`

## 1. 背景

如影 Code 已具备本地 Skill 发现与加载能力，但当前没有面向用户的市场、详情、安装、卸载和升级界面。用户需要一个参考 SkillHub 的 Skill 市场，同时满足两个使用场景：

1. 在如影 Code 桌面端中浏览和管理本机 Skill。
2. 不安装客户端也能通过独立 Web 页面浏览、搜索、查看详情、复制安装 Prompt 和下载 ZIP。

市场同时展示 SkillHub 公共目录和公司维护的企业精选目录。企业精选由公司 OSS 上的远程索引维护，不需要随客户端发版。

## 2. 已确认的产品决策

- 功能只进入 `ruying-code-oem`，不改变上游 `dev` 的默认体验。
- 市场采用独立全屏页面，入口位于桌面端侧边栏，并放在“设置”上方。
- 页面信息架构、密度、固定浅色视觉和详情结构尽量一比一参考 SkillHub。
- 数据采用混合模式：SkillHub 全量市场加公司 OSS 企业精选。
- Skill 默认安装到当前用户的全局 Skill 目录，所有项目可用。
- 首版包含浏览、搜索、筛选、详情、安装、卸载、检查更新和升级。
- 风险 Skill 可以安装，但必须先展示风险并要求二次确认。
- 独立 Web 按 SkillHub 的方式工作：允许浏览、复制 Prompt 和下载 ZIP，不直接写入本机 Skill 目录，也不强制唤起客户端。
- 社区能力不进入首版，包括收藏、评论、发布和 SkillHub 账号同步。
- 第三方 API Key 仅显示需求标签，首版不代管密钥。

## 3. 目标与非目标

### 3.1 目标

- 提供稳定、可搜索和可筛选的统一 Skill 目录。
- 让桌面端用户在不重启应用的情况下完成安装、升级和卸载。
- 让独立 Web 与桌面端共享数据模型、页面组件和视觉表现。
- 在单一远程来源故障时保留另一来源以及本地已安装管理能力。
- 在安装前验证包结构和来源，升级失败时保留旧版本。
- 支撑至少 2 万条 Skill 的列表、搜索和筛选。

### 3.2 非目标

- 不实现 SkillHub 登录、收藏、评论、发布或社交关系。
- 不在 Web 页面中直接修改用户文件系统。
- 不自动执行 Skill 中的脚本，也不在安装时收集第三方 API Key。
- 不自动删除已经安装但后来下架的 Skill。
- 不将该功能默认合并到上游 `dev`。

## 4. 用户体验

### 4.1 桌面端入口

侧边栏在“设置”上方增加 `Skills` 入口。点击后进入独立全屏市场，而不是设置弹窗、抽屉或外部网页。

页面固定使用浅色 SkillHub 风格，即使如影 Code 当前采用深色主题，市场区域也保持浅色。外层标题栏和窗口行为仍属于如影 Code。

### 4.2 市场列表

列表页包含：

- 标题、Skill 总数和搜索框。
- 全部、推荐精选、近期飙升、下载量和最近上新排序。
- 来源、场景分类和是否需要 API Key 筛选。
- 列表和卡片视图切换。
- 企业精选和已安装两个独立入口。
- 图标、名称、描述、分类、来源、评分、下载量、风险和安装状态。

搜索输入使用防抖。分页、排序和筛选由服务端执行，前端不一次性加载完整目录。

### 4.3 Skill 详情

详情使用可分享的独立路由，页面包含：

- 面包屑、图标、名称、描述、版本、更新时间、来源和风险等级。
- 概述、版本历史和安全报告页签。
- 作者、评分、下载量和分类。
- 与当前环境对应的主要操作。

桌面端主要操作为安装、安装中、已安装、可更新或卸载。Web 端主要操作为复制安装 Prompt 和下载 ZIP。

### 4.4 安装与管理

- 普通 Skill 点击安装后直接进入进度状态。
- 风险 Skill 先展示来源、风险说明和安全报告，再要求明确确认。
- 安装成功后立即刷新 Skill 服务和页面状态，无需重启应用。
- 升级使用临时目录，完成校验后原子替换；失败时保留旧版本。
- 卸载要求二次确认。
- 网络不可用时，“已安装”页面仍可管理本地 Skill。
- 下架 Skill 不会被自动删除，只显示风险或下架提示。

## 5. 总体架构

系统由远程市场后端、OSS、共享市场 UI、桌面端本地 Sidecar 和现有 Skill 服务组成。

```text
SkillHub ─────────────┐
                     ├─> 远程市场后端 ─> 版本化目录 / 图标 / 包缓存（OSS）
企业精选 OSS 索引 ────┘              │
                                     ├─> 独立 Web
                                     │
                                     └─> 桌面端本地 Sidecar ─> 安装器 ─> 全局 Skill 目录
                                                                  │
                                                                  └─> Skill 服务刷新
```

### 5.1 依赖边界

- 公共目录和本地安装 DTO 放在 Schema 层。
- HTTP API 合约放在 Protocol 层。
- 远程市场后端和本地安装处理器位于 Server 边界，不向 App 暴露 Core 或 Server 运行时代码。
- App 只依赖生成的客户端、Schema 和 Protocol 类型。
- 修改公共 Protocol 或 Server `HttpApi` 后，从 `packages/client` 执行 `bun run generate`，不直接修改生成目录。

### 5.2 共享前端

市场页面组件位于 App 包内，并通过数据提供器隔离环境差异：

- Web 数据提供器直接访问远程市场 API。
- Desktop 数据提供器通过本地 Sidecar 访问目录，并读取本机安装状态。
- 列表、详情、筛选、浅色样式和错误状态复用。
- 操作区根据运行环境切换为 Web 下载能力或 Desktop 安装能力。

## 6. 远程市场后端与 OSS

### 6.1 后端职责

远程后端负责：

- 定时同步 SkillHub 元数据。
- 读取并验证企业精选索引。
- 统一名称、描述、分类、标签、版本、评分、下载量、风险和下载信息。
- 构建分页与搜索索引。
- 发布版本化目录到 OSS。
- 提供列表、筛选项、详情、版本历史和下载接口。
- 缓存热门图标、详情内容和已验证 ZIP。
- 保留最近一次成功目录，避免来源短时故障导致市场整体不可用。

SkillHub 适配器是独立边界。SkillHub 字段或地址改变时，只调整适配器，不改变统一 DTO、App 页面或安装器。

### 6.2 OSS 布局

OSS 使用不可变版本加原子指针：

```text
skill-market/
  current.json
  indexes/<revision>/catalog.json
  indexes/<revision>/facets.json
  indexes/<revision>/details/<source>/<skill-id>.json
  assets/icons/<sha256>
  packages/<source>/<skill-id>/<version>/<sha256>.zip
  web/<release>/...
```

同步任务先完整写入 `indexes/<revision>`，验证数量、Schema 和引用完整性后，再更新 `current.json`。客户端永远通过 `current.json` 获取一个完整版本。

独立 Web 默认发布到现有如影 Code OSS 目录下的 `/ai-coding/ruying-code/skill-market/`。CDN 或静态站点规则将 `/skills/*` 回退到 Web 入口，保证详情 URL 可直接访问和分享。

### 6.3 企业精选索引

企业索引使用带版本的 JSON：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-07-15T00:00:00Z",
  "skills": [
    {
      "id": "enterprise-example",
      "source": "enterprise",
      "featured": true,
      "name": "企业示例 Skill",
      "description": "企业维护的示例技能",
      "category": "企业效率",
      "version": "1.0.0",
      "package": {
        "url": "https://example.invalid/enterprise-example-1.0.0.zip",
        "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
      }
    }
  ]
}
```

企业条目既可定义自有 Skill，也可通过 `source: "skillhub"` 和相同 ID 引用 SkillHub 条目并覆盖展示名称、分类及企业精选标记。风险等级取两个来源中更严格的结果，企业配置不能静默降低风险。

示例中的域名仅用于说明 Schema，生产索引必须通过配置指定的公司 OSS HTTPS 域名验证。

### 6.4 同步频率与失效

- SkillHub 目录每 10 分钟增量同步一次。
- 企业索引每 2 分钟检查 ETag；后台管理发布后也可主动触发同步。
- 来源失败不覆盖最近一次成功版本。
- 连续同步失败会记录结构化错误并触发运维告警。
- 企业紧急下架在下一次企业同步后生效。

## 7. 数据模型

### 7.1 列表模型

`MarketSkillSummary` 包含：

- `id`、`source`、`sourceUrl`。
- `name`、`description`、`iconUrl`。
- `categories`、`tags`、`requiresApiKey`。
- `risk`、`version`、`updatedAt`。
- `downloads`、`favorites`、`score`。
- `featured`、`enterprise`、`delisted`。
- Desktop 返回时附加 `installedVersion` 和 `updateAvailable`。

### 7.2 详情模型

`MarketSkillDetail` 在列表模型上增加：

- Markdown 概述。
- 作者和来源声明。
- 版本历史。
- 安全报告和风险说明。
- ZIP 下载描述、文件列表、大小和 SHA-256。
- 复制安装 Prompt 所需的公开详情 URL。

所有外部 Markdown 在 Web 和 Desktop 渲染前执行相同的安全清理，不允许脚本、事件属性或不受信任的嵌入内容。

## 8. API 设计

### 8.1 远程只读 API

```text
GET /v1/catalog/skills
GET /v1/catalog/facets
GET /v1/catalog/skills/:source/:id
GET /v1/catalog/skills/:source/:id/versions
GET /v1/catalog/skills/:source/:id/download
```

列表请求支持 `query`、`source`、`category`、`requiresApiKey`、`sort`、`page` 和 `limit`。默认 `limit` 为 30，最大为 100。下载接口返回经过验证的 OSS 地址或短时签名跳转。

### 8.2 Desktop 本地 API

```text
GET    /api/skill/market/skills
GET    /api/skill/market/skills/:source/:id
GET    /api/skill/market/installed
GET    /api/skill/market/updates
POST   /api/skill/market/install
POST   /api/skill/market/update
DELETE /api/skill/market/install/:source/:id
```

本地目录接口代理远程市场并合并安装状态。安装和升级请求必须携带 `source`、`id`、`version` 和预期 SHA-256；风险条目还必须携带用户确认标记。服务端重新验证风险和哈希，不能信任前端状态。

## 9. 本地安装器

### 9.1 安装位置

Skill 安装到 `path.join(Global.Path.config, "skills", skillID)`。在 Unix 系统通常对应 `~/.config/opencode/skills/<skill-id>`，Windows 使用平台配置目录。该目录属于当前用户，因此所有项目都可发现。

### 9.2 安装流程

1. 获取目录详情和预期哈希。
2. 下载 ZIP 到同一文件系统上的临时目录。
3. 校验 HTTPS 来源、响应大小和 SHA-256。
4. 检查 ZIP 路径、文件数量、解压大小和压缩比。
5. 拒绝绝对路径、路径穿越、空路径、符号链接和硬链接。
6. 解压到 staging 目录。
7. 验证 `SKILL.md`、frontmatter 名称和目录 ID。
8. 原子替换目标目录，并在失败时恢复旧版本。
9. 刷新 Skill 服务并发布安装状态变化事件。

默认安全限制为：压缩包 50 MiB、解压后 200 MiB、2,000 个文件、100:1 最大压缩比。限制由 OEM 配置集中提供，但客户端不能关闭路径和链接检查。

同一个 Skill 的安装、升级和卸载通过 Skill ID 锁串行执行；不同 Skill 可以有限并发。

### 9.3 Skill 服务刷新

现有 Skill 服务增加显式刷新能力。安装器完成原子写入后触发刷新，并发布状态事件。刷新失败不回滚已经验证并安装的文件，但 UI 显示“已安装，加载失败”，允许重试刷新，不要求重启进程。

## 10. 安全与信任

- 远程目录、详情、图标和包只允许 HTTPS。
- 请求目标限制在 OEM 配置的 SkillHub、市场 API 和公司 OSS 域名。
- 目录条目必须具有稳定来源、版本和哈希。
- 首次缓存 SkillHub ZIP 时由后端计算哈希并将其固定到发布版本。
- 风险等级显示来源，风险 Skill 必须二次确认。
- 远程 Markdown 使用允许列表清理，链接默认使用安全打开策略。
- 安装只写全局 Skill 根目录，不跟随包内路径逃逸。
- 安装阶段不执行包内脚本。
- 后端保留同步版本、来源 URL、哈希和下架操作审计记录。
- Web 和 Desktop 明确展示 Skill 来源、作者与原始详情链接；同步和缓存不得移除原始许可声明。
- 日志不记录 Skill 正文、用户项目路径、剪贴板内容或 API Key。

## 11. 缓存、离线与错误处理

### 11.1 缓存

- 远程后端使用 OSS 版本化快照和 ETag。
- 本地 Sidecar 保存最近一次成功目录元数据，不缓存不受信任的渲染结果。
- Web 使用标准 HTTP 缓存；HTML 短缓存，带内容哈希的静态资源长缓存。
- 图标失败时显示来源首字母占位，不阻塞列表。

### 11.2 部分失败

- SkillHub 失败时继续展示企业精选和上次成功的 SkillHub 快照。
- 企业索引失败时继续展示 SkillHub 和上次成功企业快照。
- 没有任何远程快照时显示可重试错误页。
- 本地“已安装”页面不依赖远程市场。

### 11.3 用户可见错误

错误转换成稳定代码和可读文案，包括：

- 网络不可用。
- 市场暂时不可用。
- Skill 已下架。
- 风险尚未确认。
- 包损坏或哈希不匹配。
- 包结构不安全。
- 磁盘空间或权限不足。
- 版本冲突。
- 安装成功但 Skill 刷新失败。

## 12. 性能设计

- 远程 API 负责分页、搜索、排序和筛选。
- 列表使用虚拟滚动，图标懒加载。
- 搜索防抖并取消过期请求。
- 列表模型不携带完整 Markdown 或版本历史。
- 详情和安全报告按需加载。
- 后端对搜索索引和热点详情建立缓存。
- 单一来源同步采用限流并发，防止对来源站点形成突发请求。

性能验收基线：

- 20,000 条目录下，缓存命中的列表 API P95 小于 300 ms。
- 常规公司网络下首屏可交互时间小于 2 秒。
- 搜索输入停止后 500 ms 内展示服务端响应或加载状态。
- 列表连续滚动不出现持续主线程阻塞。

## 13. 测试策略

### 13.1 后端与来源

- 使用固定响应样本测试 SkillHub 字段变化、缺失字段和异常响应。
- 使用真实本地 HTTP 服务测试分页、筛选、缓存、ETag 和超时。
- 测试版本化索引完整发布、指针切换和失败不覆盖旧版本。
- 测试单一来源故障、双来源故障和 OSS 回退。
- 使用 20,000 条以上目录运行搜索和并发性能测试。

### 13.2 安装器

- 使用真实临时目录和真实 ZIP，不复制生产解析逻辑到测试中。
- 覆盖正常安装、重复安装、升级、卸载和刷新。
- 覆盖路径穿越、绝对路径、符号链接、硬链接、ZIP bomb、超限文件和损坏包。
- 覆盖哈希不匹配、下载中断、磁盘失败、升级回滚和同 Skill 并发操作。
- 验证风险未确认时服务端拒绝安装。

### 13.3 Web

- 覆盖列表、卡片、筛选、搜索、分页和详情深链接。
- 覆盖固定浅色视觉、响应式布局和键盘操作。
- 覆盖复制 Prompt、ZIP 下载、来源归属和风险展示。
- 覆盖空目录、部分来源失败、无缓存和资源加载失败。

### 13.4 Desktop

- 覆盖侧边栏入口、列表和详情导航。
- 覆盖安装、风险确认、立即可用、更新、升级和卸载。
- 覆盖网络离线时的已安装管理。
- 端到端验证安装后无需重启即可被 Skill 服务发现。

## 14. 发布与运维

- OEM 配置提供市场总开关、远程 API、企业索引、允许域名和安装限制。
- 市场关闭时不显示侧边栏入口，本地已有 Skill 仍按现有机制工作。
- 独立 Web 静态资源发布到 OSS，并保留上一个 release 便于回滚。
- 远程目录发布保留多个 revision，`current.json` 可以快速回退。
- 后端记录同步耗时、来源成功率、条目数量、缓存命中率、下载结果和错误码。
- 不采集用户安装的 Skill 正文、项目目录或第三方密钥。
- 企业紧急下架只影响市场可见性和更新，不远程删除用户文件。

## 15. 实施分段

该功能横跨远程后端、Web 和 Desktop，实施按可独立验证的边界分段：

1. 定义 Schema、Protocol、企业索引格式和测试样本。
2. 实现 SkillHub/企业来源适配、目录同步、OSS 原子发布和远程只读 API。
3. 实现共享市场页面和独立 Web 的浏览、详情、复制 Prompt 与 ZIP 下载。
4. 实现本地安装器、刷新能力和 Desktop 本地 API。
5. 将共享页面接入 Desktop，并完成安装、升级、卸载和风险确认。
6. 完成 20,000 条性能验证、端到端验收、OSS 发布与回滚演练。

每一段在进入下一段前保持可测试且不破坏现有 Skill 加载路径。远程目录和 Web 可先独立发布；Desktop 安装入口只在远程 API、包校验和回滚测试全部通过后启用。

## 16. 验收标准

满足以下条件后首版可交付：

1. 独立 Web 和桌面端均能浏览同一份 SkillHub 加企业精选目录。
2. Web 可搜索、筛选、打开可分享详情、复制 Prompt 和下载 ZIP。
3. Desktop 可安全安装、卸载和升级，并在不重启的情况下刷新可用 Skill。
4. 风险 Skill 未明确确认时无法安装。
5. 包损坏或升级失败不会破坏已有版本。
6. 任一远程来源故障时，另一来源和最近成功快照仍可使用。
7. 网络完全不可用时，Desktop 仍可管理已安装 Skill。
8. 20,000 条目录达到性能基线。
9. 固定浅色页面在如影 Code 和独立 Web 中保持一致。
10. 社区入口不出现在首版页面中。
