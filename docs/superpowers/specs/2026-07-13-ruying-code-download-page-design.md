# 如影 Code 下载页设计

## 目标

为长城汽车内部研发人员提供一个独立、可信且易部署的如影 Code 桌面客户端下载页。页面介绍产品价值，自动推荐当前操作系统对应的安装包，并始终保留 macOS 与 Windows 两个平台的直接下载入口。

## 交付形式

下载页使用无框架的静态文件实现：`index.html`、`styles.css`、`app.js` 与本地品牌资源。产物不依赖服务端、构建工具、接口或第三方 CDN，可作为一个目录直接上传到 OSS 或任意静态服务器。

页面代码放在 OEM 工作树内的独立目录，不接入现有 `packages/web` 官网，也不修改桌面应用运行逻辑。

## HTTP-only 部署契约

当前下载页必须通过 HTTP 来源部署，不得把页面发布到 HTTPS 来源。两个已批准的安装包地址仅提供 HTTP；如果由 HTTPS 页面跳转到这些地址，浏览器可能把下载识别为不安全的混合内容并阻止用户获取安装包。保留 HTTP 地址是明确的产品决定，不得替换成证书链尚未获得浏览器信任的 HTTPS 地址。

只有当两个安装包都具备浏览器可信的 HTTPS 地址，或部署方提供同源 HTTPS 代理时，页面才可以切换到 HTTPS。切换时必须在同一个变更中同步更新 `index.html`、`app.js`、包 README、设计与实施文档，以及固定 URL、无脚本下载和网络边界测试。

生产 `index.html`、`app.js` 和 `styles.css` 只能包含下文列出的两个外部安装包 URL。页面初始加载只能请求自身来源的 HTML、CSS、JavaScript 和本地图标，不得请求分析、身份或业务接口。

## 目标用户与文案定位

目标用户是长城汽车内部研发人员。页面使用简体中文，明确它是企业研发工具，并突出以下价值：

- 理解现有代码和项目上下文。
- 协助修改、运行与验证代码。
- 通过企业 SSO 使用内部身份登录。

核心标题采用“让每一次编码，都有如影相随。”，正文避免夸大能力或使用未经确认的数据指标。

## 信息结构

### 顶部导航

左侧显示如影 Code 正式图标和产品名，右侧提供“产品能力”“下载安装”“安装说明”三个页内锚点。移动端只保留品牌与主要下载入口，避免引入菜单组件。

### 首屏

首屏采用深色沉浸科技风格，包括克制的紫色光晕、细网格背景和高对比排版。内容顺序为：

1. “长城汽车内部研发工具”标识。
2. 产品主标题和一句简短介绍。
3. 根据当前系统变化的主下载按钮。
4. 跳转到双平台下载区的次要按钮。
5. 简短的系统支持说明。

### 产品能力

使用三张精简卡片介绍“读懂项目”“协作修改”“企业 SSO”。卡片只包含图形符号、标题和一段说明，不展示虚构截图或指标。

### 下载区

macOS 与 Windows 使用两张并列卡片：

- macOS：Apple Silicon，下载 DMG。
- Windows：x64，下载 EXE。

当前系统对应的卡片显示“推荐”标识。另一平台入口始终可见且可操作。

下载链接固定为：

- macOS：`http://app-platform.oss-cn-baoding-gwmcloud-d01-a.res.cloud.gwm.cn/ai-coding/ruying-code/ruying-code-desktop-mac-arm64.dmg`
- Windows：`http://app-platform.oss-cn-baoding-gwmcloud-d01-a.res.cloud.gwm.cn/ai-coding/ruying-code/ruying-code-desktop-win-x64.exe`

### 安装说明

页面为两个平台分别提供三步以内的安装说明。当前安装包未签名，因此明确提示用户可能遇到 macOS 安全限制或 Windows SmartScreen，并给出简洁、合规的处理指引，不暗示安装包已签名。

### 页脚

页脚注明“仅供长城汽车内部研发使用”，重复产品名称，不添加尚未提供的帮助中心、隐私协议或联系方式链接。

## 交互设计

`app.js` 使用 `navigator.userAgent` 判断 macOS 或 Windows：

- macOS：首屏主按钮指向 DMG，macOS 卡片显示“推荐”。
- Windows：首屏主按钮指向 EXE，Windows 卡片显示“推荐”。
- 其他或无法识别：首屏按钮显示“选择下载版本”，点击后滚动到下载区，不预选平台。

系统识别只影响推荐状态，不隐藏或改写任何原始下载链接。页面不请求接口、不读取身份、不采集或上传用户信息。

当 JavaScript 被禁用时，两个平台卡片中的普通 `<a>` 下载链接仍然有效。平滑滚动和装饰动画遵循 `prefers-reduced-motion`；键盘用户可清楚看到焦点状态。

## 响应式与可访问性

- 桌面端使用宽内容容器和双列下载卡片。
- 平板与手机端切换为单列，按钮宽度适配触控操作。
- 正文与背景保持足够对比度，装饰性光晕不承载信息。
- 使用语义化标题、导航、主内容、区块与页脚元素。
- 图标提供适当的替代文本；纯装饰图形对辅助技术隐藏。
- 下载链接具有清晰的平台、架构与文件格式说明。

## 失败与降级处理

- 系统识别失败时让用户自行选择平台。
- JavaScript 失败时保留所有核心内容和下载链接。
- OSS 文件不可用时由浏览器展示网络错误；静态页不伪造成功状态，也不引入额外重试逻辑。
- 图标资源加载失败时仍显示文本产品名。

## 验收标准

1. 页面可作为纯静态目录打开和部署，无第三方运行时依赖。
2. macOS、Windows 和未知系统分别呈现正确的主按钮行为。
3. 两个下载链接与需求提供的 OSS 地址完全一致。
4. 禁用 JavaScript 后仍可从下载卡片获取两个安装包。
5. 桌面宽屏、平板和手机尺寸下无横向溢出或重叠。
6. 键盘可访问所有链接与按钮，并有清晰焦点样式。
7. `prefers-reduced-motion` 下不执行非必要动画或平滑滚动。
8. 页面包含产品介绍、双平台下载、企业 SSO 能力和未签名安装提示。
9. 页面不发起分析、身份或业务接口请求。
10. 页面按 HTTP-only 契约部署；生产源码只包含两个批准的 HTTP 安装包 URL，本地浏览器预览也使用 HTTP。

## 不在本次范围内

- 自动更新、版本接口、文件大小与发布时间展示。
- 登录、SSO 回调或用户身份读取。
- 下载统计、埋点或分析平台。
- Linux 安装包。
- 多语言、内容管理系统和服务端渲染。
- 安装包签名、公证或发布流程调整。
