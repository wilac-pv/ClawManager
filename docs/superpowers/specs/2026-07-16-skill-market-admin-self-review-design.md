# Skill 市场 Admin 自审权限设计

## 目标

调整 Skill 市场的审核权限，使 Admin 可以审核所有投稿，包括自己提交的 Skill；普通 Reviewer 仍然不能审核自己的投稿。所有审核决定继续写入现有审核记录和审计日志。

## 权限规则

服务端是审核授权的唯一可信来源：

- Admin 可以审核任何处于 `pending_review` 状态的投稿，包括投稿人是自己的情况。
- Reviewer 可以审核其他员工的投稿，但不能审核自己的投稿。
- 没有 Reviewer 或 Admin 角色的用户不能访问审核接口。
- 现有状态校验、乐观并发版本校验、审核意见校验和风险确认规则保持不变。

Admin 自审不引入额外复核步骤，也不新增角色或权限字段。

## 服务端设计

`SkillMarketSecurity.requireReviewTarget` 继续先要求调用者具备 Reviewer 或 Admin 权限。若调用者拥有 Admin 角色，则允许审核任意投稿；否则，当调用者工号与投稿人工号相同时返回现有 `forbidden` 错误。

`moderation.decide` 继续调用该安全边界，不在业务层重复角色判断。审核成功后沿用现有事务，原子写入：

- `reviews` 审核记录；
- `submissions` 状态和版本；
- 通过审核时的 `publish_jobs`；
- `audit_events` 审计事件。

Admin 自审的审计记录使用 Admin 本人工号作为 `actor_employee_id`，因此无需迁移数据库或修改审计结构。

## Web 设计

审核详情页已经接收服务端会话派生的 `admin` 标志。页面将“自审受限”定义为：投稿人是当前用户，并且当前用户不是 Admin。

- Admin 查看自己的投稿时，不显示“不能审核自己的投稿”，审核表单保持可用。
- Reviewer 查看自己的投稿时，继续显示现有提示并禁用审核表单。
- 页面状态只用于交互反馈；即使客户端状态被篡改，服务端仍按角色重新授权。

## 错误处理与审计

Reviewer 自审继续返回稳定的 `forbidden` 错误，前端保持现有禁止提示。Admin 自审仍可能因投稿状态变化、版本冲突、缺少审核意见或风险确认而失败，这些错误沿用现有处理。

所有成功决定继续记录审核人、决定、审核意见、风险接受说明、投稿状态变化和版本变化。权限放开不减少审计信息。

## 测试

采用测试驱动实现，并覆盖以下行为：

1. 安全矩阵允许 Admin 审核自己的投稿，同时拒绝 Reviewer 自审。
2. Admin 自审通过后只产生一条审核记录、一个发布任务和一条包含 Admin 工号的审计事件。
3. Web 审核页对 Admin 自有投稿启用审核表单，不显示禁止提示。
4. Web 审核页对 Reviewer 自有投稿继续禁用审核表单并显示禁止提示。
5. 现有并发决定、风险确认、审核意见和状态校验测试保持通过。

## 发布与回滚

该变更同时涉及服务端授权和 Web 交互，因此发布新的不可变 API release 与 Web release：

1. 先运行 Server 与 Web 测试、类型检查和生产构建。
2. 安装并切换新的 API release，重启 Skill 市场 API，验证健康检查和会话接口。
3. 安装并切换新的 Web release，验证审核详情深链接和静态资源。
4. 保留当前 API 与 Web release 作为回滚点。

若任一线上验证失败，先恢复 Web 软链，再恢复 API 软链并重启服务。数据库结构不变，不需要数据回滚。

## 非目标

- 不允许普通 Reviewer 审核自己的投稿。
- 不新增独立的 `canReviewOwn` 权限。
- 不改变投稿状态机、发布流程、角色管理或审计数据模型。
