# 如影 Code App SSO 登录设计

日期：2026-07-12  
状态：已批准

## 背景

如影 Code 已经具备共享 App 登录组件和服务端 GWM SSO ProviderAuth 流程，但正式 `prod` 构建默认使用旧版布局，而 `RuyingGate` 只包裹新版布局。旧版布局因此可以绕过登录页，直到执行模型请求时才收到“请先运行 `ruying-code login`”的非交互错误。

现有 App 登录按钮还只把授权地址渲染为链接，没有通过共享平台接口自动打开系统浏览器；登录成功后则通过整页重载刷新状态。桌面应用应当直接提供完整登录流程，不要求用户先在终端执行登录命令。

## 目标

- 正式版旧布局和新版布局都必须经过同一个如影登录门禁。
- 用户点击登录后自动使用系统默认浏览器完成 GWM SSO。
- Web 版使用同一流程，在新标签页打开授权地址。
- 登录页提供等待状态、备用链接、取消和可重试错误。
- 登录成功后在当前窗口同步状态并进入主界面，不重启或整页重载应用。
- 继续复用 CLI、TUI 和 App 共用的 ProviderAuth、回调、开通和凭据持久化实现。

## 非目标

- 不使用内嵌浏览器承载 GWM SSO。
- 不从桌面端启动或解析 `ruying-code login` 子进程。
- 不改为 `ruying-code://` 自定义协议回调。
- 不重写现有服务端 SSO、9527 回调、Token 开通或凭据存储逻辑。
- 不移除非交互 CLI 的 `ruying-code login` 操作提示。
- 不改变现有页面视觉风格、主题或品牌布局。

## 方案选择

采用“共享布局门禁 + 现有 ProviderAuth + 平台外链”的方案。

未采用以下方案：

- 桌面端包装 CLI 子进程：会重复处理进程生命周期、输出解析、取消和状态刷新，且 Web 版无法复用。
- 自定义协议回调：需要 GWM SSO 支持协议回调，并新增协议注册与安全校验，超出当前必要范围。
- 内嵌浏览器：增加认证兼容性和安全风险，也不符合用户选择的系统浏览器体验。

## 架构

### 统一门禁

`SelectedServerProviders` 已经为旧版和新版主界面提供当前服务器的 `ServerSDKProvider` 与 `ServerSyncProvider`。`RuyingGate` 放入这层共同上下文，使两个布局在渲染业务界面前都执行权威登录检查。

新版布局删除原有的专用 `RuyingGate` 包裹，避免重复检查和重复事件订阅。门禁仍以当前选中的服务器为作用域；服务器切换会销毁旧控制器，并针对新服务器重新检查状态。

### 登录控制器

共享 App 的登录控制器依赖以下窄接口：

- `authorize`：调用 `provider.oauth.authorize`，启动服务端回调监听并返回授权 URL。
- `openLink`：调用共享 `Platform.openLink`。桌面版经 Electron IPC 使用系统默认浏览器，Web 版打开新标签页。
- `callback`：调用 `provider.oauth.callback`，等待浏览器回调和服务端开通流程完成。
- `cancel`：调用 `provider.oauth.cancel`，停止当前授权尝试并释放回调资源。
- `bootstrap`：重新同步当前服务器状态。
- `status`：调用 `provider.ruying.status` 做登录后的权威复查。

控制器保持与 Solid 组件分离，以便用真实状态转换做单元测试而不模拟服务端内部实现。

## 数据流

1. 当前服务器同步就绪后，门禁调用 `provider.ruying.status`。
2. 未登录时只显示全屏登录页，不渲染旧版或新版业务界面。
3. 用户点击“SSO 登录”，控制器进入 `pending` 并调用 `authorize`。
4. 收到授权 URL 后立即调用 `openLink`，同时在登录页显示完整备用链接。
5. 控制器调用 `callback` 等待 GWM SSO 回调。
6. 服务端复用现有流程，把 SSO Token 交给开通服务换取个人 API Key，并持久化凭据与身份。
7. 回调成功后，App 执行 `bootstrap`，再调用 `status`。
8. 只有权威状态返回 `loggedIn: true` 时才恢复 `idle` 并让门禁原地展示主界面。
9. 若权威状态未生效，App 保留在登录页并显示可重试错误，不使用 `window.location.reload()`。

## 界面状态

### 未登录

- 展示现有如影品牌登录页。
- 显示“使用 GWM SSO 登录”主按钮。
- 不暴露受保护的主界面内容。

### 登录中

- 显示“正在等待浏览器完成 SSO 登录”。
- 显示完整授权 URL，允许点击或复制作为自动打开失败时的备用入口。
- 显示“取消登录”按钮。
- 禁止并发启动第二个登录尝试。

### 登录成功

- 重新同步当前服务器。
- 权威复查登录状态。
- 原地进入主界面，不重载窗口。

### 登录失败

- 回到可重试状态并保留明确中文错误。
- 不把失败或缺失响应解释为成功。
- Token 待管理员开通、超时、端口占用、SSO 失败和网络失败优先展示服务端提供的可操作信息。

## 取消、并发与生命周期

- 取消操作调用 `provider.oauth.cancel`，服务端负责关闭当前回调监听。
- 每次登录、取消或服务器切换都会推进本地尝试编号。
- 异步步骤完成时必须核对尝试编号；陈旧授权、回调、同步或状态响应不得覆盖当前状态。
- 组件卸载或服务器切换后，旧请求即使完成也不能更新新服务器的界面。
- 服务端现有五分钟回调超时继续作为最终超时边界。

## 错误处理

- `authorize` 失败：显示无法启动 SSO 的原因并允许重试。
- `openLink` 失败：授权流程继续等待，显示点击或复制备用链接的提示。
- `callback` 失败：显示服务端错误；若没有安全可展示的信息则使用通用中文提示。
- `cancel` 失败：退出取消中状态，显示失败原因并允许再次取消或重试。
- `bootstrap` 失败：不进入主界面，提示同步失败。
- `status` 失败或仍为未登录：不进入主界面，提示登录状态未生效。

错误消息不得包含 API Key、SSO Token、回调查询参数或其他凭据。

## 改动边界

主要修改：

- `packages/app/src/app.tsx`：统一旧版和新版布局的登录门禁。
- `packages/app/src/components/ruying-login.tsx`：系统浏览器、取消、原地同步和权威复查。
- `packages/app/src/components/ruying-login.test.tsx`：登录状态机单元测试。
- `packages/app/src/components/ruying-wiring.test.tsx` 及必要的 App 壳测试：上下文接线和两个布局的门禁覆盖。

除非失败测试证明现有接口不足，否则不修改服务端 ProviderAuth 或公共 HttpApi。如果必须修改公共 Protocol 或 Server HttpApi，需从 `packages/client` 运行 `bun run generate`，不直接编辑生成目录。

## 测试策略

按 TDD 顺序增加并验证以下行为：

- 正式 `prod` 默认的旧版布局也被登录门禁拦截。
- 新版布局仍被拦截，且不会出现双重门禁或双重订阅。
- `authorize` 返回 URL 后，在等待 `callback` 前调用 `openLink`。
- 自动打开失败时保留备用链接并允许流程继续。
- 登录中可以取消，取消成功后回到未登录状态。
- 登录成功后依次执行 `bootstrap` 和权威 `status`，不调用页面 reload。
- 权威状态未登录或状态请求失败时继续停留在登录页。
- 新登录、取消、组件卸载和服务器切换会忽略陈旧异步响应。

验证命令从对应包目录执行：

1. App 定向测试。
2. App `bun typecheck`。
3. Desktop `bun typecheck` 与生产构建。
4. 使用个人 `packaging-ruying-code` 技能生成未签名 macOS arm64 DMG/ZIP。
5. 复核 DMG、ZIP、应用名称、Bundle ID、生产图标、无 Developer ID 签名和 SHA-256。

## 验收标准

- 全新或已退出登录的正式 macOS 安装包启动后直接显示 SSO 登录页。
- 旧版和新版布局均不能绕过登录门禁。
- 点击登录会自动打开系统默认浏览器，无需运行终端命令。
- 浏览器未自动打开时，用户可从界面的备用链接继续登录。
- 用户可以取消进行中的登录并重新尝试。
- SSO 成功后当前窗口直接进入主界面，不重启或整页重载。
- 登录失败、超时、待开通和状态未生效均留在登录页并显示可操作错误。
- 登录后仍只暴露如影 Provider；现有 CLI/TUI SSO 行为不回归。
- 新生成的未签名 DMG/ZIP 通过完整性和品牌校验。
