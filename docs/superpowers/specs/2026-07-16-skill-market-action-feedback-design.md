# Skill 市场操作反馈修复设计

## 背景与根因

线上登录、会话读取、投稿列表和角色列表接口均正常。实际访问记录中没有出现失败的角色写请求，说明“添加角色”的问题发生在请求发出之前。

当前角色表单在员工工号为空时直接禁用“添加角色”，但按钮仍保持蓝色主按钮外观，用户会将无反馈的点击理解为系统失效。市场首页的“投稿 Skill”则完全依赖 JavaScript 路由回调；虽然现有测试和线上访问记录都能到达投稿页，但 Web 入口缺少原生链接的可观察、可恢复行为。

## 目标

- Web 市场的“投稿 Skill”始终表现为带正确基础路径的真实链接。
- “添加角色”在缺少工号时仍可触发，并在表单附近显示明确错误。
- 真正不可操作的等待状态具有清晰的禁用视觉和鼠标反馈。
- 桌面端继续使用现有回调打开投稿网址，不改变桌面行为。

## 方案

### 投稿入口

为共享的 `SkillMarketList` 增加可选 `submitHref`。当传入链接时渲染原生 `<a>`；没有链接但传入 `onSubmit` 时继续渲染按钮。Web 使用包含 Vite `BASE_URL` 的投稿链接，桌面端保留 `onSubmit` 回调。

链接和按钮共用同一视觉类，补充链接所需的布局、文本装饰和盒模型样式，确保外观不变。

### 角色表单

只在网络请求处理中禁用“添加角色”。提交空工号时不发请求，直接显示“请输入员工工号。”，并复用现有错误区域。用户开始编辑后错误自动清除。

所有 `.market-primary-action:disabled` 使用降低透明度和 `not-allowed` 光标，避免等待状态看起来仍可点击。

## 未采用方案

- 继续保持空工号时禁用、仅增加灰色样式：能解释状态，但用户仍无法通过点击得到具体原因。
- 仅在 Web 页面外层新增一个独立投稿链接：会复制共享列表的标题布局，并使 Web 与桌面入口更难保持一致。

## 测试

- 共享列表组件测试：传入 `submitHref` 时渲染正确链接且不调用回调；仅传入回调时继续渲染按钮。
- 角色表单测试：空工号点击显示校验错误且不调用后端；填写工号后仍能成功添加。
- Web 端到端测试：投稿入口使用带部署基础路径的 `href`，点击后到达投稿页面。
- 运行 Skill 市场 Web 浏览器测试、相关 App 组件测试、两包类型检查和生产构建。

## 发布与验证

修复合并后生成新的不可变 Web release，切换服务器 Web `current` 软链；API 无需重启。线上验证投稿链接、空工号校验、有效角色添加请求和基础路径均正常，旧 Web release 保留用于回滚。
